# M6: optional model host wiring

Research date: 2026-11-10. Scope: completing the existing single-call pipeline through
Discord interactions and the authenticated HTTP endpoint. No live model was called.

## Primary sources

- [Discord interaction responses](https://docs.discord.com/developers/interactions/receiving-and-responding),
  read 2026-11-10: acknowledge within three seconds; a type-5 deferred reply can later
  be edited. The initial response sets ephemeral visibility. Implementation: always
  defer `/ask` and catch-up before awaiting the model, then edit the original reply.
- [Anthropic Messages](https://platform.claude.com/docs/en/api/http/messages), read
  2026-11-10: `/v1/messages` accepts a system prompt and messages and reports input and
  output token usage. Reuse the existing adapter and persistent reservation ledger.
- [LM Studio Chat Completions](https://lmstudio.ai/docs/developer/openai-compat/chat-completions)
  and [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility),
  read 2026-11-10: both support the Chat Completions shape used by the existing
  OpenAI-compatible adapter. Local Ollama ignores the client key. Document loopback
  setup; keep actual hosted/local acceptance pending.
- [BotChecker](https://github.com/versionDefect/BotChecker), repository README read
  2026-11-10: a related Discord bot advertises BYOK providers and citation checking.
  This is prior art, not evidence for our implementation. Retain local source-id
  validation and no tool use; do not adopt its web fact-checking workflow.
- [discord.js issue #11554](https://github.com/discordjs/discord.js/issues/11554), opened
  2026-06-14, read 2026-11-10: a user reports deferral timeout leaving the SDK unable to
  edit the response. This is a report about another SDK, not a verified twilight bug.
  Our service makes the deferral before calling the provider, and has fake-transport
  tests; real acknowledgement and edit failures remain part of the live checks.
- [picoclaw issue #1048](https://github.com/sipeed/picoclaw/issues/1048), opened
  2026-03-04, read 2026-11-10: missing replied-message context was reported and linked
  to PR #1047. Keep the existing bounded neighbour retrieval; do not add live link
  fetching or a tool loop to this task.

## Choices and pending evidence

Inject a backend into each interface rather than adding server-to-LLM or
Discord-to-LLM dependency edges. Share one provider and ledger in the binary. Discord
questions use member/channel scope; access tokens read all included data and pay from
their own budgets because the token schema has no member link. Keep query expansion
deferred until an eval measures its benefit (plan section 11).

Fakes cover both transports, input and output framing, citation/URL filtering, budget
exhaustion, provider errors and catch-up summaries. These checks cannot establish
real model answer quality, real token accounting or Discord delivery. M6 acceptance
still needs one hosted and one local model, and the Discord live gates.
