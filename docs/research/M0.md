Date: 2026-11-04. Scope: Cargo workspace, toolchain/MSRV, cargo-deny, GitHub Actions hardening,
cargo-dist readiness, Windows CI. Sources were checked on 2026-11-04 unless another date is
given. Repo files were read with `gh api` (read-only) at the commit/tag shown. Reddit and X

## 1. Workspace conventions

**What others do.**
- Edition 2024 is standard for new code: [twilight 0.18](https://github.com/twilight-rs/twilight/blob/twilight-0.18.0/Cargo.toml),
  [rmcp 3.8](https://github.com/modelcontextprotocol/rust-sdk/blob/rmcp-v3.8.0/Cargo.toml),
  rusqlite 0.41, clap 4.6, uv, ruff, rust-analyzer. Older libraries (tokio, axum, reqwest) stay on 2021.
- `[workspace.package]` carries version, edition, rust-version, license, repository (atuin, rmcp, twilight, rust-analyzer).
- `[workspace.lints]` is used by axum, uv, ruff, rust-analyzer; members opt in with `[lints] workspace = true`
  ([Cargo book](https://doc.rust-lang.org/cargo/reference/workspaces.html), checked 2026-11-04).
  axum sets `unsafe_code = "forbid"`; uv/ruff only `warn`.
- Resolver: a virtual workspace must set it explicitly. rmcp and twilight use `"3"`; uv, atuin and rust-analyzer still say `"2"`.
  Resolver 3 (edition-2024 default, Rust 1.84+) makes `cargo update`/new deps prefer versions compatible with
  `rust-version` and falls back rather than erroring ([Cargo book: resolver](https://doc.rust-lang.org/cargo/reference/resolver.html)).
- Toolchain pin: uv and ruff `channel = "1.99.0"`, atuin `1.98.0`, rmcp `"1.96"`. Dependabot can bump
  `rust-toolchain.toml` via the `rust-toolchain` ecosystem ([changelog 2025-08-19](https://github.blog/changelog/2025-08-19-dependabot-now-supports-rust-toolchain-updates/)).
- xtask: [rust-analyzer](https://github.com/rust-lang/rust-analyzer/blob/master/.cargo/config.toml) defines
  `[alias] xtask = "run --package xtask --bin xtask --"` in `.cargo/config.toml`; its `xtask/Cargo.toml` has `publish = false`,
  inherits `rust-version`/lints and notes "Avoid adding more dependencies to this crate".
- `.gitattributes` `* text=auto eol=lf`: uv and ruff.
- uv sets `+crt-static` for MSVC so the Windows binary needs no VC++ redistributable ([uv .cargo/config.toml](https://github.com/astral-sh/uv/blob/main/.cargo/config.toml); ruff issue 11503, closed).
- atuin sets `LIBSQLITE3_FLAGS = "-DSQLITE_DEFAULT_MEMSTATUS=0"` in `.cargo/config.toml`; libsqlite3-sys 0.39 honours that variable
  ([build.rs](https://github.com/rusqlite/rusqlite/blob/v0.41.1/libsqlite3-sys/build.rs)) and already enables FTS5 for `bundled`.

**What broke.** Dependabot cargo PRs ignore `rust-version` (open issue [dependabot-core#5423](https://github.com/dependabot/dependabot-core/issues/5423), title only read). twilight says
its MSRV "may change in minor or patch releases" ([README](https://github.com/twilight-rs/twilight/blob/twilight-0.18.0/README.md)). An MSRV job on the committed lockfile is the catch.

**We'll do.** Edition 2024, resolver 3, workspace-inherited package fields and lints, `publish = false` on every crate,
exact-pinned toolchain, xtask via alias, LF everywhere, static CRT on Windows MSVC.

Current stable: Rust **1.99.1** (2026-10-16; [releases](https://github.com/rust-lang/rust/releases)); GitHub runners ship 1.99.1 and rustup 1.29.2
([ubuntu-24.04 image](https://github.com/actions/runner-images/blob/main/images/ubuntu/Ubuntu2404-Readme.md)). 1.89.0 is from 2025-08-07 (about 15 months old).
Peers: tokio keeps a rolling "at least 6 months" MSRV; atuin 1.95, uv 1.97, rust-analyzer 1.98.

**How MSRV is tested.** rmcp reads `rust_version` from `cargo metadata` and runs `cargo +$MSRV check --all-targets --all-features`
([ci.yml](https://github.com/modelcontextprotocol/rust-sdk/blob/main/.github/workflows/ci.yml)); tokio runs a `minrust` check job. Both use `check`, not `test`.

**We'll do.** MSRV = **1.89** (the highest floor among planned deps). Rule: MSRV is set by the dependencies, bumps are allowed in
minor releases, and each bump is a CHANGELOG line. CI job `msrv` installs it and runs `cargo +<rust-version> check --workspace --all-targets --locked`.
(At M0 there are no deps, so the job only proves the wiring; real value starts in M1.)

## 3. cargo-deny and cargo-audit

**Facts.** cargo-deny **0.20.2** (2026-07-09, MSRV 1.88; [CHANGELOG](https://github.com/EmbarkStudios/cargo-deny/blob/main/CHANGELOG.md)). Config sections:
`[graph] [advisories] [licenses] [bans] [sources]`. Schema notes from the [docs](https://github.com/EmbarkStudios/cargo-deny/tree/main/docs/src/checks):
- licenses: everything not in `allow` is denied; `deny`, `default`, `copyleft`, `unlicensed` are removed and error.
- advisories: `yanked` default `warn`, `unmaintained` default `all`, `unsound` default `workspace`; `vulnerability`/`severity-threshold` removed.
  The docs contradict themselves on `unsound` (cargo-deny's own deny.toml still sets it); we leave it at the default. `ignore-expiry` is **unreleased** (not in 0.20.2).
- bans: `wildcards`, `allow-wildcard-paths` (private path deps only), and a newer `[bans.workspace-dependencies]` check (`duplicates`, `unused` both default `deny`):
  every dependency declared twice must use `workspace = true`, and a `[workspace.dependencies]` entry nothing uses fails. So M0 must declare only deps it uses.
- Real configs: [atuin](https://github.com/atuinsh/atuin/blob/main/deny.toml) (`unmaintained = "workspace"`, `yanked = "deny"`, `wildcards = "deny"`, `CDLA-Permissive-2.0` allowed),
  [axum](https://github.com/tokio-rs/axum/blob/main/deny.toml) (`unmaintained = "none"`, `multiple-versions = "deny"` with a skip list), cargo-deny's own.

**Licences our planned stack needs** (from crates.io metadata, latest versions): twilight-* is **ISC**; rustls-webpki ISC; ring `Apache-2.0 AND ISC`;
aws-lc-sys `ISC AND (Apache-2.0 OR ISC) AND Apache-2.0 AND MIT AND BSD-3-Clause ...` (no OpenSSL clause in 0.47); rmcp Apache-2.0; unicode-ident `(MIT OR Apache-2.0) AND Unicode-3.0`;
icu_* Unicode-3.0; encoding_rs `(Apache-2.0 OR MIT) AND BSD-3-Clause`; subtle BSD-3-Clause; foldhash/zlib-rs Zlib; webpki-roots CDLA-Permissive-2.0 (only if that feature is chosen).
reqwest 0.13's default TLS is rustls + **aws-lc-rs** + platform verifier ([Cargo.toml](https://github.com/seanmonstar/reqwest/blob/v0.13.5/Cargo.toml));
twilight's default is `rustls-platform-verifier`, plus `zstd-safe` (another C build). Which crypto provider wins is an M1 decision.

**What broke for others.** cargo-deny 0.20.0 refactored the CLI, which broke cargo-deny-action v2.1.0 until v2.1.1 ([action#113](https://github.com/EmbarkStudios/cargo-deny-action/issues/113),
[#114](https://github.com/EmbarkStudios/cargo-deny-action/issues/114)); `all-features = true` merges features of every member and trips bans on optional TLS crates
([cargo-deny#792](https://github.com/EmbarkStudios/cargo-deny/issues/792)); `unmaintained = "all"` fails on any transitive unmaintained crate.

**cargo-audit vs cargo-deny.** Both read the RustSec DB. cargo-deny adds licences/bans/sources and handles yanked/unmaintained/unsound policy;
cargo-audit adds `bin` scanning of built binaries ([README](https://github.com/rustsec/rustsec/blob/main/cargo-audit/README.md)). For a lockfile-only check they are redundant.
rmcp runs cargo-audit alone; atuin and axum use cargo-deny. **Recommendation:** drop `cargo-audit` from PR CI (deviation from plan §16, needs maintainer OK);
run `cargo deny check` on PRs and `cargo deny check advisories` on a daily schedule, because new advisories appear without any code change.

**We'll do.** Install with `taiki-e/install-action` pinned `cargo-deny@0.20.2` (the Docker-based deny-action does not run on Windows/macOS and has had CLI-coupling breakage). `deny.toml` below.

## 4. GitHub Actions hardening

**What others do.** rmcp ([ci.yml](https://github.com/modelcontextprotocol/rust-sdk/blob/main/.github/workflows/ci.yml), [scorecard.yml](https://github.com/modelcontextprotocol/rust-sdk/blob/main/.github/workflows/scorecard.yml),
[codeql.yml](https://github.com/modelcontextprotocol/rust-sdk/blob/main/.github/workflows/codeql.yml)): all actions SHA-pinned with `# vX.Y.Z` comments, top-level `permissions: contents: read`,
CodeQL matrix incl. `rust` and `actions`, and a comment citing tj-actions as the reason to be careful in the release job. uv: `persist-credentials: false` on checkouts, a zizmor job,
`rustup toolchain install "$RUSTUP_TOOLCHAIN" --profile minimal` instead of a toolchain action, `concurrency` with `cancel-in-progress`. tokio: `defaults.run.shell: bash` so steps are identical on Windows.

**Incidents (why pin).** tj-actions/changed-files: tags repointed to a malicious commit, March 2025 ([CISA alert, 2025-03-18](https://www.cisa.gov/news-events/alerts/2025/03/18/supply-chain-compromise-third-party-github-action-cve-2025-30066)).
2026 reports of tag poisoning (Trivy actions, actions-cool) come from secondary press ([THN 2026-05](https://thehackernews.com/2026/05/github-actions-supply-chain-attack.html),
[THN 2026-09](https://thehackernews.com/2026/09/compromised-github-actions-came-back.html)); treat as leads. A pinned SHA does not help if the SHA itself was malicious.

**Facts that shape the design.**
- Runners already have Rust 1.99.1 and rustup 1.29.2 on ubuntu-24.04 and windows-2025; macOS images are also listed ([runner-images](https://github.com/actions/runner-images)).
  rustup auto-installs the toolchain named in `rust-toolchain.toml` on first use (default since 1.28.1, [CHANGELOG](https://github.com/rust-lang/rustup/blob/main/CHANGELOG.md)).
  So **no toolchain action is needed**, which removes `dtolnay/rust-toolchain` (it takes the toolchain from its ref name, so hash-pinning it is awkward).
- `-latest` labels drift (macos-latest is macOS 26 arm64, windows-latest is Windows Server 2025); use explicit labels: `ubuntu-24.04`, `macos-26`, `windows-2025`.
- zizmor 1.32.0 ([docs](https://docs.zizmor.sh/audits/)): audits include `unpinned-uses`, `artipacked` (needs `persist-credentials: false`), `excessive-permissions` (wants `permissions: {}` at top),
  `template-injection`, `cache-poisoning`, `dependabot-cooldown` (default minimum 7 days), `superfluous-actions`. `zizmorcore/zizmor-action` defaults to `advanced-security: true` (SARIF upload, no job failure);
  set `advanced-security: false` and `annotations: true` to make PRs fail on findings ([action.yml](https://github.com/zizmorcore/zizmor-action/blob/v0.8.0/action.yml)).
- Scorecard action: job may only use `actions/checkout`, `actions/upload-artifact`, `github/codeql-action/upload-sarif`, `ossf/scorecard-action`, `step-security/harden-runner`;
  no top-level `env`/`defaults`; `id-token: write` and `security-events: write` on that job only; supported triggers `push` and `schedule` (default branch only); `pull_request`/`workflow_dispatch` are experimental, rmcp also adds `branch_protection_rule`
  ([README](https://github.com/ossf/scorecard-action)).
- CodeQL for Rust is GA since 2025-10-14, no build needed ([changelog](https://github.blog/changelog/2025-10-14-codeql-scanning-rust-and-c-c-without-builds-is-now-generally-available));
  `build-mode: none` is an `init` input. Enabling **default setup disables a custom CodeQL workflow** ([troubleshooting](https://docs.github.com/en/code-security/reference/security-at-scale/troubleshoot-security-configurations/unexpected-default-setup)),
  so keep default setup off and use the advanced workflow. Advanced setup counts as inactive after 90 days without analysis, hence a weekly schedule.
- Codecov: tokenless upload works only for fork PRs; otherwise a token or `use_oidc: true` is required ([README](https://github.com/codecov/codecov-action)). That means a third-party account,
  which is outward-facing. M0 uses `cargo llvm-cov --lcov` + job summary + `upload-artifact`; Codecov (OIDC) can be added later.
- Dependabot `cooldown` (`default-days`) is supported for cargo and github-actions; it does not apply to security updates; `groups` take `patterns` and `update-types`
  ([options reference](https://docs.github.com/en/code-security/dependabot/working-with-dependabot/dependabot-options-reference)).
- Repo setting worth enabling (ask first): "require actions to be pinned to a full-length commit SHA" ([changelog 2025-08-15](https://github.blog/changelog/2025-08-15-github-actions-policy-now-supports-blocking-and-sha-pinning-actions/)); enforced at run time.
- Windows line endings: with `core.autocrlf=true` on Windows runners, CRLF checkouts break `rustfmt` with `newline_style = "Unix"` and byte-exact `insta` snapshots; the fix used by uv/ruff is `* text=auto eol=lf` (rustfmt#3939 and project `.gitattributes` files; search-level evidence).
  Long paths: `git config --system core.longpaths true` is the usual workaround; add it only if a path-length failure appears (lead, not needed yet).

**We'll do.** Everything in "Decisions" below.

## 5. cargo-dist (for M8; M0 only keeps the door open)

cargo-dist/`dist` is at **0.34.0** (2026-11-02); uv uses 0.32, atuin 0.31 ([releases](https://github.com/axodotdev/cargo-dist/releases)). Config now lives in `dist-workspace.toml`
(`[workspace] members = ["cargo:."]`, `[dist]`), see [atuin](https://github.com/atuinsh/atuin/blob/main/dist-workspace.toml): `github-attestations = true`, `installers = ["shell","powershell"]`,
`targets`, `pr-run-mode`, and `[dist.github-action-commits]` to pin the actions dist generates (without it `dist plan` fails on drift). Facts from the [book](https://github.com/axodotdev/cargo-dist/tree/main/book/src):
dist detects distributable apps from binaries, ignores `publish = false` packages unless `dist = true`, needs `repository` set to emit GitHub CI/installers, and needs `[profile.dist]`
(`dist init` adds it). Toolchain pinning via `rust-toolchain.toml` is the supported route (`rust-toolchain-version` is deprecated). Attestations need a public repo (ours is); the book still calls the GitHub feature "public beta" (stale; unverified).

**What broke for others.** `x86_64-unknown-linux-musl` with a C dependency needs `musl-tools` via a custom `build-setup.yml` ([#1753](https://github.com/axodotdev/cargo-dist/issues/1753); that report is C++, ours is C, so unverified for SQLite);
Windows arm64 + `ring` fails ([#1825](https://github.com/axodotdev/cargo-dist/issues/1825)); installer paths with spaces on Windows ([#2337](https://github.com/axodotdev/cargo-dist/issues/2337)); dist-generated workflows lag `actions/checkout` ([#2508](https://github.com/axodotdev/cargo-dist/issues/2508)).

**We'll do (M0 only).** Single app crate `crates/teamctx` (package name `teamctx`), `xtask` and all libraries `publish = false`, `repository`/`license`/`description` set via workspace inheritance,
no `[profile.dist]` yet, no workflow named `release.yml`. Add an early musl + bundled SQLite build check in M1 spike S4, not M8.

## 6. Windows gotchas

- Bundled SQLite compiles through the `cc` crate with MSVC; runners include Visual Studio, and libsqlite3-sys `bundled` enables FTS3/FTS5/JSON1/RTREE ([build.rs](https://github.com/rusqlite/rusqlite/blob/v0.41.1/libsqlite3-sys/build.rs)). `links = "sqlite3"` means one SQLite version per graph; keep rusqlite as the only owner.
- Use `shell: bash` as the default for `run` steps on all three OSes (tokio does).
- Static CRT (`+crt-static`) for MSVC avoids the VC++ redistributable requirement (ruff#11503).
- LF checkout via `.gitattributes`; do not put `newline_style = "Unix"` in a rustfmt.toml (no `rustfmt.toml` needed).

## Decisions for the M0 scaffold

### Root `Cargo.toml`
```toml
[workspace]
resolver = "3"
members = ["crates/*", "xtask"]

[workspace.package]
version = "0.0.0"
edition = "2024"
rust-version = "1.89"
license = "MIT OR Apache-2.0"
repository = "https://github.com/koolestasian/discord-team-context"  # update when the name is final (open question 1)
publish = false

[workspace.dependencies]
# Only internal path crates at M0. cargo-deny's workspace-dependencies check fails on unused entries.
teamctx-core = { path = "crates/teamctx-core" }
# ...store, discord, llm, server likewise

[workspace.lints.rust]
unsafe_code = "forbid"
rust_2018_idioms = { level = "warn", priority = -1 }
missing_debug_implementations = "warn"
unreachable_pub = "warn"

[workspace.lints.clippy]
unwrap_used = "deny"            # plan: no unwrap/expect outside tests; use #[expect(clippy::expect_used, reason = "...")] for proven-infallible spots
expect_used = "deny"
todo = "deny"
unimplemented = "deny"
dbg_macro = "deny"
mem_forget = "deny"
allow_attributes = "warn"       # prefer #[expect(..., reason = "...")]
allow_attributes_without_reason = "warn"
str_to_string = "warn"
manual_let_else = "warn"
implicit_clone = "warn"
needless_pass_by_value = "warn"
cloned_instead_of_copied = "warn"
large_futures = "warn"
```
Each crate: `version.workspace = true`, `edition.workspace = true`, `rust-version.workspace = true`, `license.workspace = true`, `repository.workspace = true`, `publish.workspace = true`, `[lints] workspace = true`, plus a `description`.
Dependency edges per plan §5.1 (`bin -> discord/server/llm -> store -> core`); `core` has no dependencies. All names above were confirmed to exist in rust-clippy `main` (declared_lints.rs); none was run. Delete any the 1.99.1 clippy rejects.
Not adopted: blanket `clippy::pedantic` (uv/ruff need ~20 allows), `print_stdout/print_stderr` (CLI needs stdout; cannot be scoped per crate with inherited lints).

`clippy.toml`: `allow-unwrap-in-tests = true`, `allow-expect-in-tests = true`, `allow-panic-in-tests = true`, `allow-dbg-in-tests = true` (defaults are `false`; clippy reads `msrv` from `rust-version`).

### Workflows (all: top-level `permissions: {}`, per-job `contents: read`, `persist-credentials: false`, `timeout-minutes`, `defaults.run.shell: bash`, `CARGO_TERM_COLOR=always`, `RUSTFLAGS=-D warnings`; plan §16 says `read-all`, `{}` plus per-job grants is stricter and what zizmor asks for)
1. **`ci.yml`** (push to `main`, `pull_request`; `concurrency` cancel-in-progress). Jobs:
   - `fmt` (ubuntu-24.04): `rustup toolchain install` (reads the toolchain file) then `cargo fmt --all -- --check`.
   - `clippy` (matrix ubuntu-24.04, macos-26, windows-2025): `cargo clippy --workspace --all-targets --locked -- -D warnings`.
   - `test` (same matrix): `cargo test --workspace --locked`.
   - `msrv` (ubuntu): read `rust-version` with `cargo metadata --no-deps --format-version 1 | jq -r '.packages[0].rust_version'`; `rustup toolchain install $V --profile minimal`; `cargo +$V check --workspace --all-targets --locked`.
   - `deny` (ubuntu): install `cargo-deny@0.20.2`; `cargo deny check`.
   - `coverage` (ubuntu): install `cargo-llvm-cov@0.9.1`, `rustup component add llvm-tools-preview`, `cargo llvm-cov --workspace --locked --lcov --output-path lcov.info`, write `cargo llvm-cov report` to `$GITHUB_STEP_SUMMARY`, upload `lcov.info` as an artifact. Not gating in M0.
   - `ci-ok` (needs all above, `if: always()`, fails if any need failed): the single required status check for the main ruleset.
   Rust cache: `Swatinem/rust-cache` with `save-if: ${{ github.ref == 'refs/heads/main' }}`.
2. **`audit.yml`**: `schedule` daily + `workflow_dispatch`; installs cargo-deny, runs `cargo deny check advisories`. (cargo-audit omitted; see section 3.)
3. **`codeql.yml`**: push/PR to `main`, weekly cron; matrix `language: [rust, actions]`, `build-mode: none`; job perms `security-events: write`, `contents: read`.
4. **`scorecard.yml`**: as rmcp's (push to `main`, weekly cron, `branch_protection_rule`); `publish_results` only on the default branch; only the allowed actions.
5. **`zizmor.yml`**: push/PR touching `.github/**`; `advanced-security: false`, `annotations: true` so findings fail the PR; `security-events: write` not needed in that mode.
6. **`.github/dependabot.yml`** (`version: 2`), three updates, each `cooldown: { default-days: 7 }` (documented for cargo and github-actions; unverified for `rust-toolchain`, drop it there if rejected): `cargo` (weekly; group `minor-and-patch` with `update-types: [minor, patch]`; `open-pull-requests-limit: 5`),
   `github-actions` (weekly; one group `actions`), `rust-toolchain` (monthly). Majors arrive as individual PRs. Because Dependabot ignores `rust-version`, a cargo PR that breaks the MSRV job is the signal to pin or bump MSRV deliberately.
7. Not in M0: `release.yml` (dist, M8), container image (M8), dependency-review (duplicates cargo-deny), Codecov.
