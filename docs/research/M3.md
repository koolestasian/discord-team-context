# M3 offline connector prior art

Research date: 2026-11-05. Scope: permissions, bot invite, configuration and offline
init/doctor. Live ingestion, token validation and interaction replies remain gated on
S1/S2 in a throwaway server.

- [Discord permission hierarchy](https://docs.discord.com/developers/topics/permissions):
  compute everyone base plus role union, everyone overwrite, aggregated role deny/allow,
  then member deny/allow. Administrator and guild ownership bypass overwrites. Role
  ordering must not affect the result. View denial makes history unreadable even if the
  history bit remains set. Tests cover these boundaries and extra permissions warnings.
- [Discord bot authorization](https://docs.discord.com/developers/topics/oauth2#bot-authorization-flow):
  the bot scope authorizes guild installation; application commands are included by
  default, but are explicit in our invite. The local builder fixes permissions to
  1024 | 65536 = 66560 and accepts numeric IDs so query parameters cannot be injected.
- [Discord gateway privileged intents](https://docs.discord.com/developers/events/gateway#privileged-intents):
  requesting an intent and enabling it in the portal are separate requirements. The
  setup guide asks for Message Content, without Presence or Server Members.
- [Official API docs issue 4775](https://github.com/discord/discord-api-docs/issues/4775)
  (GitHub search lead: message content missing despite intent settings) prompted an
  explicit separation of offline token presence from live content-access verification.
  No behavior is inferred from the issue; the gateway documentation is authoritative.
- [Official message resource](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx)
  documents empty history results without Read Message History. Seeing live events is
  therefore insufficient evidence of backfill permissions.
- [toml deserialization API](https://docs.rs/toml/latest/toml/fn.from_str.html): use serde
  typed configuration with unknown-field rejection, not a bespoke TOML parser. `serde`
  derives and `toml` are approved plan section 17 dependencies, introduced when first
  used. Standard library alone was considered; it does not parse the plan's TOML format.

Reddit and X were searched. Reddit search-result leads about denied history still
being visible highlighted role overwrite interactions; those observations were checked
against Discord's algorithm rather than treated as requirements. X returned no useful
primary implementation evidence. No social claim is used as a factual specification.

The offline doctor must not imply successful Discord authentication or effective access
without fetching guild/member/channel data. It reports deferred URL/timezone validation,
Windows ACL checks and private-thread membership explicitly. It never echoes a parsed
value or parser source excerpt on an error, because a pasted token could occupy that
field. Tokens remain in process environment variables; secrets.env loading is deferred.
