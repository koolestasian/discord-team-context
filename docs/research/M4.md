# M4 agent surfaces prior art

## Agent Skill and `teamctx skill install`

Research date: 2026-11-09. Scope: the Agent Skill format, where agents read skills, and
the connect commands printed by `teamctx token create`. Every item below was read on the
page named, not recalled.

- [Agent Skills specification](https://agentskills.io/specification) (read 2026-11-09).
  A skill is a directory with a `SKILL.md`: YAML frontmatter, then Markdown. `name` is
  required, at most 64 characters of lowercase letters, digits and single hyphens, no
  leading or trailing hyphen, and it must match the parent directory name. `description`
  is required, 1 to 1,024 characters, and should say what the skill does and when to use
  it. `license`, `compatibility` (at most 500 characters), `metadata` and the experimental
  `allowed-tools` are optional. Agents load only name and description at startup, the full
  body when the skill activates; the page recommends a body under 500 lines and about
  5,000 tokens. Our `SKILL.md` uses `name`, `description` and `compatibility` only, and a
  unit test enforces the name, description, compatibility and size limits from this page.
- [How to add skills support to your agent](https://agentskills.io/client-implementation/adding-skills-support)
  (read 2026-11-09). The page lists user-level scan locations `~/.<client>/skills/` and
  `~/.agents/skills/`, and calls `.agents/skills/` a "widely-adopted convention for
  cross-client skill sharing" while saying the specification does not mandate locations.
  So we install to `~/.agents/skills/teamctx/` as well as the Claude Code folder.
- [Claude Code skills](https://code.claude.com/docs/en/skills) (read 2026-11-09).
  Personal skills live in `~/.claude/skills/<skill-name>/SKILL.md` and load in all
  projects. The page does not list `~/.agents/skills`, so the Claude Code folder is
  installed explicitly. `description` is recommended; the description plus
  `when_to_use` is truncated at 1,536 characters in the skill listing, so the use case
  comes first and the description is about 300 characters. Angle brackets in a
  description are shown escaped; ours has none (a test checks).
- [Codex skills](https://developers.openai.com/codex/skills) (read 2026-11-09). Codex
  scans `$HOME/.agents/skills` for user skills and `.agents/skills` from the working
  directory up to the repository root, and follows symlinked skill folders. That makes
  `~/.agents/skills/teamctx/` the Codex location. Our installer never writes through a
  symlink, so a symlinked skill folder is reported, not replaced.

Decisions that follow:

- `teamctx skill install` writes `~/.claude/skills/teamctx/SKILL.md` and
  `~/.agents/skills/teamctx/SKILL.md`. `--dir PATH` writes `PATH/teamctx/SKILL.md` only.
- No overwrite of a differing file without `--force`. Both targets are checked before
  either is written, so a conflict never leaves a half install. The home directory is read
  from `USERPROFILE` (Windows) or `HOME`, and only when absolute.
- No YAML dependency: the frontmatter is three plain one-line values, and the test that
  guards it rejects anything a YAML reader could parse differently.

## Connect commands printed by `token create`

- [Claude Code MCP](https://code.claude.com/docs/en/mcp) (read 2026-11-09):
  `claude mcp add --transport http <name> <url>` and
  `claude mcp add --transport http secure-api https://api.example.com/mcp --header "Authorization: Bearer your-token"`;
  `--scope` picks where the configuration is stored (local, project, user). The plan's
  example abbreviates `--header` to `-H`; the docs show the long form, so we print that.
- [Codex MCP](https://developers.openai.com/codex/mcp) (read 2026-11-09). Streamable HTTP
  servers go in `~/.codex/config.toml` as `[mcp_servers.<name>]` with `url` and
  `bearer_token_env_var` (the name of an environment variable holding the token, sent as
  `Authorization: Bearer`). `codex mcp add` is documented for stdio servers
  (`-- <command>`) and for `--url` with OAuth options; a bearer-token flag is not
  documented, so we print the TOML table rather than an add command.
- [Cursor MCP](https://cursor.com/docs/mcp) (read 2026-11-09). `~/.cursor/mcp.json` or
  `.cursor/mcp.json` with `{"mcpServers": {"<name>": {"url": ..., "headers": {...}}}}`;
  values may use `${env:NAME}`, and the docs' own example is
  `"Authorization": "Bearer ${env:MY_SERVICE_TOKEN}"`.

Decision: the printed commands refer to the token through `TEAMCTX_TOKEN` instead of
repeating it. The token then appears once in the output (the existing test checks this),
Codex and Cursor never store it in their config files, and the same variable is what
`teamctx q` reads.

Not verified: none of the three clients was run against a live host in this task (there
is no `teamctx run` host command yet). The commands and file formats match the
documentation quoted above.
